# 文档附件管家（siyuan-plugin-attachment-kit）v0.6.5

**安装**：思源「设置 → 集市 → 从本地安装」，选 `siyuan-plugin-attachment-kit.zip`；或把目录整个放进 `工作空间/data/plugins/siyuan-plugin-attachment-kit/`，重启后在「已下载」里启用

---

## 1 一句话概括

**给思源笔记补上「一篇文档里的附件，名字跟着正文里的锚文本走、需要时一键整套导出」这件事——你不用再一个个点开附件改名字，也不用为了交稿再挨个右键另存。**

它替你做的两件事：

（1）你正文里写 `[06发表论文](assets/xxx-20261004174122-ZzCpTJB9.pdf)`，插件把磁盘上那个文件改名叫 `06发表论文-20261004174122-ZzCpTJB9.pdf`，本文档里所有指向它的链接一起改对；

（2）你在菜单里点「导出全部附件」，插件按正文出现顺序把这一篇的附件和图片编成 `001-`、`002-`…，拷进一个随机命名的临时文件夹，导完自己把文件夹弹出来。

两件事**都只作用于当前文档**——菜单头上写着哪一篇，就只动哪一篇。

## 2 主要功能

### 2.1 按锚文本改附件名

点菜单第一项即执行，不弹窗、不预览、不二次确认。

| 锚文本 | 原链接 | 改后 |
|---|---|---|
| `AAAAA.doc`（带后缀） | `assets/旧名-20261103101532-e3bi598.wps` | `assets/AAAAA-20261103101532-e3bi598.doc` |
| `AAAAA`（不带后缀） | `assets/旧名-20261103101532-e3bi598.wps` | `assets/AAAAA-20261103101532-e3bi598.wps` |

- **只对齐词干**，思源的 `-时间戳-7位随机码` 保留不删；原文件没有就现造一段 `-YYYYMMDDHHmmss-xxxxxxx`。
- 锚文本自带时间戳（别的工具留下的）先剥再拼，不会叠成两份。
- 锚文本不写扩展名时，用附件自己的扩展名。
- 锚文本里的 `\ / : * ? " < > |` **直接过滤**：`报告/终:版.wps` → `报告终版-<戳>.wps`。
- **空格原样保留**，不转 `%20`、不换下划线、不加反斜杠（思源自己写带空格的链接也是原样空格）。

### 2.2 一键导出全部附件（含图片）

点菜单第二项即执行，导完自动弹文件夹。

| 项 | 规则 |
|---|---|
| 范围 | 当前文档正文里**直接引用**的本地附件，图片也算 |
| 顺序 | 在正文里出现的先后顺序 |
| 编号 | `001-`、`002-`… 三位，**缺文件跳过且不占号**，编号始终连续 |
| 文件名 | 剥掉思源的 `-时间戳-随机码`：`06发表论文_asset_031-20261004174122-ZzCpTJB9.pdf` → `001-06发表论文_asset_031.pdf` |
| 撞名 | 剥戳后重名的第二个起加 `-2`、`-3`，扩展名保留 |
| 目录 | `%TEMP%\思源附件-<yyyyMMdd-HHmmss>-<6位随机>\`，**随机命名，连点两次不会互相覆盖** |
| 超长名 | 全路径逼近 Windows 260 上限时自动截断（扩展名保住、留 `…`），提示里报「N 个名字过长已截断」 |
| 收尾 | 自动打开该文件夹；打不开时提示里给出完整路径 |

导出的是**副本**：思源库里的原文件、文档内容一概不动。

### 2.3 一个顶栏图标，两件事

顶栏图标（蓝色方块）点一下弹出自绘下拉菜单，头部先报数：

```
文档附件管家
当前文档 · 共 88 个附件（12 张图片）
────────────────────────────────
按锚文本改附件名
一键导出全部附件
```

- 定位贴上沿自动内收，不会跑出屏幕；点别处或按 `Esc` 关闭。
- 颜色全部取思源 `--b3-*` 变量，**亮 / 暗主题自动跟随**，不用手动切。

### 2.4 作用域：只扫当前文档

| 动作 | 扫哪儿 | 碰哪些文件 |
|---|---|---|
| 改附件名 | 只扫当前文档的链接 | 只改当前文档引用到的附件（其他文档引用的是同一个文件，自然一起生效） |
| 导出 | 只扫当前文档的链接 | 不碰原文件，只在临时目录写副本 |

- **不递归子文档**。
- 被块引用 / 嵌入带进来的附件（正文里是 `((块ID))`）不算本文档引用，不处理。
- 文档 ID 在**菜单打开那一刻**就锁定，之后焦点漂到别的标签页也不影响。

> 「会改全库引用」是**结果**不是**范围**：改名后别的文档里指向同一文件的链接必须跟着改，否则就是断链。插件真正做的，是「只把这一篇的附件名改对，并保证别处不受影响」。

### 2.5 改名的六道保险

（1）**先备份**：旧文件复制到 `工作空间/data/anchor-backup/<时间戳>/`，确认没问题再自己删；

（2）**先复制再删**：新文件建好、引用逐块校验通过、复查无残留之后，才删旧文件；

（3）**引用改 0 处就回滚**：全库搜不到任何指向该文件的引用，说明判断有误，直接放弃，不删不改；

（4）**任一步失败全体回滚**：已改的块逐块还原、新文件删掉、旧文件原样保留；

（5）**只改最内层块**：列表 / 引用 / 超级块里改的是里面的段落，不重写容器，子块 ID 不变；

（6）**防连点**：上一轮没跑完再点只提示「上一轮还在处理」。

### 2.6 什么情况不动

点一次只改「干净」的条目，其余跳过并在提示里报数：

| 状态 | 意思 |
|---|---|
| 已一致 | 目标名和现名相同，不处理也不计数 |
| 后缀不一致 | 锚文本写 `.doc`、文件其实是 `.wps`，按锚文本改名会把类型说错 |
| 目标文件已存在 | `assets/` 里已有同名文件，静默跳过 |
| 同文件多个目标 | 同一附件被几条链接指向却算出不同目标名，全部拦下 |
| 磁盘上找不到 | 链接指向的文件不在 `assets/` 里 |
| 名字非法 / 过长 | 过滤后为空，或超过 200 字节 |
| 空锚文本 | 方括号里是空的 |
| 路径异常 | 链接里是 `%xx` 转义路径，或写成 `assets/assets/xxx`，不猜 |

### 2.7 提示语

改完只回一条 toast，不打断干活：

```
改名 12 个附件，改写引用 18 处（2 个文件名含空格，按原样保留）；另有 3 处不动（后缀不一致×1、已一致×2）
已导出 55 个附件（含 12 张图片，38.4 MB，跳过 2 个找不到的），已打开文件夹
```

- 「改写引用 18 处」= 本文档里有多少条链接跟着改了名。
- 后缀不一致、目标已存在、同文件多目标这些**不改也不报错**的条目，归到「另有 N 处不动」里分类计数。

## 3 破解了思源笔记的哪些问题

### 3.1 附件名和锚文本长期两张皮

思源插入附件时，文件名是「时间戳-随机码」，锚文本才是你写的标题。改标题不会改文件名，攒久了 `assets/` 里全是天文数字。

→ **插件做的事**：以锚文本为准，把词干对齐到文件名上，时间戳保留（保证唯一性、也便于回溯）。

### 3.2 两条改名接口各缺一半

3.8.9 实测：`/api/asset/renameAsset` 会自动改全库引用，但**强制补回时间戳随机码**；`/api/file/renameFile` 不加时间戳，但**完全不改引用**。

→ **插件做的事**：自己拼两条路——复制成新名 → `instr` 查引用 → `updateBlock` 逐块替换 → 删旧名，并且引用改 0 处必须回滚。

### 3.3 `blocks.sort` 不可靠

同一文档里 `sort` 会出现重复值，按它排序导出的编号会乱。

→ **插件做的事**：导出不用块表排序，读整篇 `getBlockKramdown`，出现顺序即文档顺序。

### 3.4 一条链接散成三个块

同一处附件链接在块表里会是 `l`（列表）/ `i`（项）/ `p`（段落）三条记录，逐块扫会重复计数、还会算错顺序。

→ **插件做的事**：文档级 kramdown 一次拿全篇，链接天然只出现一次；改名时也按「链接 → 最内层段落」定位。

### 3.5 SQL 索引延迟

写入后立刻查 `/api/query/sql` 常返 0 行（索引滞后 0.6～2 秒，偶发更久）。

→ **插件做的事**：存在性判断走磁盘实读，写入校验一律读 `getBlockKramdown`，不读 SQL。

### 3.6 链接里残留 `%20`

库里有 76 处链接写成 `%20`，而盘上没有字面 `%20` 的文件名——不解码就全部「找不到」。

→ **插件做的事**：读路径前先 `decodeURIComponent`。

### 3.7 点顶栏按钮时当前文档会漂

点顶栏图标那一刻焦点已经跑掉，事后调 `getActiveDoc()` 可能拿到别的标签页。

→ **插件做的事**：`toggleMenu()` 里取一次文档 ID，往下传参，菜单头写哪篇就作用在哪篇。

### 3.8 `child_process` 打不开文件夹

`execFile("explorer.exe", [dir])` 在插件里**不报错、也不弹窗**，函数还返回成功。

→ **插件做的事**：走思源自己的 IPC `ipcRenderer.send("siyuan-cmd", {cmd:"openPath", filePath})`（主进程里就是 `shell.openPath`，与「设置 → 打开主题文件夹」同一条路）。

### 3.9 `LIKE` 里的 `_` 与 `%` 是通配符

拿文件名做 `content LIKE '%名%'` 会捞进大量无关块——文件名常带下划线。

→ **插件做的事**：一律 `instr(content,'名')>0`。

### 3.10 备份目录不能放进 `assets/`

放进去会被当成素材建索引，越备越多。

→ **插件做的事**：备份落 `工作空间/data/anchor-backup/`。

### 3.11 导出到临时目录会撞上 Windows 260 字符

附件名本来就长（`Yu-et-al.-2027-Straw-to-biochar-…`），`%TEMP%` 路径又深，拼起来超过 260 字符时 `copyFileSync` 直接 `ENAMETOOLONG`，整个文件导不出来。

→ **插件做的事**：按「目录长度 + 编号前缀」算出名字预算，超了从词干截断、**扩展名一定保住**、留一个 `…`，并在提示里报「N 个名字过长已截断」。

## 4 现有做法与本插件的取舍

### 4.1 思源原生能力

| 能力 | 优点 | 局限 |
|---|---|---|
| 右键附件 → 重命名 | 有个入口 | 一次只能改一个；不给建议名，全靠手打 |
| 资源文件管理面板 | 能看到全部素材 | 看不到「谁在引用它」，改名容易断链 |
| 手工改锚文本 | 改标题很自然 | 和文件名完全脱钩 |
| 逐篇导出附件 | 思源的导出功能 | 走的是整篇导出（PDF/Word），不是「只拿附件」 |

### 4.2 手工 / 第三方脚本

外部脚本能批量改名，但要自己处理「引用同步」和「失败回滚」；一旦中途出错，断链就得全库找。导出更麻烦——正文顺序得自己解析，图片和附件还得分开处理。

### 4.3 本插件的优点与代价

**优点**

（1）零配置，一个顶栏图标两个动作；

（2）改名带备份、带回滚，失败不动原状；

（3）导出保持正文顺序，编号连续，图片一并带上；

（4）只动当前文档，误操作半径小。

**代价**

（1）只认 Markdown 链接形态的锚文本，图片不参与改名（导出则包含图片）；

（2）不递归子文档，长篇连载要一篇篇来；

（3）导出的临时目录不自动清理，`%TEMP%` 里会留几天；

（4）改的是文件名，**不可撤销**——只能靠 `anchor-backup/` 手回。

## 5 主要依赖及配置

### 5.1 运行环境

| 项 | 要求 |
|---|---|
| 思源版本 | ≥ 3.1.0（实测 3.8.9） |
| 端 | **桌面端**（Windows / macOS / Linux）；手机与浏览器端没有 Node，插件不启用 |
| 依赖 | 无外部依赖，不需要联网，不调用云端 |

### 5.2 依赖的内核接口

| 接口 | 用途 |
|---|---|
| `/api/block/getBlockKramdown` | 读整篇正文（导出排序、改名定位都靠它） |
| `/api/query/sql` | 改名时预筛引用块（只做粗筛，不做判据） |
| `/api/block/updateBlock` | 逐块改链接 |
| `/api/file/renameFile` | 落新文件名 |
| `/api/asset/upload` | 上传新附件（`assetsDirPath` 不能带前导斜杠） |
| `/api/ui/reloadUI` | 开发时热重载前端 |

### 5.3 数据文件位置

| 位置 | 内容 |
|---|---|
| `工作空间/data/plugins/siyuan-plugin-attachment-kit/` | 插件本体 |
| `工作空间/data/assets/` | 附件与图片（插件只读，改名时按需重写） |
| `工作空间/data/anchor-backup/<时间戳>/` | 改名前的原文件备份 |
| `%TEMP%\思源附件-<时间戳>-<随机>\` | 导出的副本，可随时删 |

### 5.4 设置项

**没有设置面板**。所有行为固定：剥时间戳、三位编号、随机临时目录、改完弹窗。少一个开关，少一处配错。

### 5.5 三条约定（照做才不会乱）

（1）**锚文本写你希望文件叫的名字**，不包括扩展名也行，插件会补；

（2）**同一附件别写成两个不同的锚文本**，插件会判定「同文件多个目标」全部拦下；

（3）**导出的副本随便改**，它和库里的文件已经没有关系了。

## 6 触发方式与快捷键

### 6.1 顶栏图标

右侧顶栏，蓝色圆角方块（内置 SVG，不是图片 URL）。点一下开菜单，再点一下收起。

### 6.2 菜单项

| 菜单项 | 作用 |
|---|---|
| 按锚文本改附件名 | 立即执行，只回 toast |
| 一键导出全部附件 | 立即执行，导完弹文件夹 |

### 6.3 快捷键

**没有**。插件不注册快捷键，避免和思源默认键冲突；常用的话可以给顶栏图标位置记个肌肉记忆。

### 6.4 注意事项

- 菜单打开时不能同时开设置面板等带遮罩的弹窗（遮罩会盖住顶栏）。
- 上一轮没结束时再点，只提示「上一轮还在处理」，不会排队。

## 7 用法与详细操作步骤

### 7.1 安装与启用

（1）下载 `siyuan-plugin-attachment-kit.zip`；

（2）思源 → 设置 → 集市 → 从本地安装，选这个 zip；

（3）启用后顶栏右侧出现蓝色方块图标。没有就重启思源。

> zip 里的文件必须都在**根层**，套一层同名目录会导致安装后不加载。

### 7.2 按锚文本改附件名

（1）打开要整理的那篇文档（光标点进正文，让插件能认出当前文档）；

（2）点顶栏图标，看菜单头确认「就是这一篇」；

（3）点第一项，等 toast；

（4）看 toast：改了几个、改写了多少条引用、哪些没动；备份在 `data/anchor-backup/<时间戳>/`。

不满意就去 `data/anchor-backup/<时间戳>/` 把原文件拷回去——但引用已经被改成新名字了，回退要连引用一起改，一般不建议。

### 7.3 一键导出全部附件

（1）打开文档，点顶栏图标，看菜单头的「共 N 个附件（M 张图片）」；

（2）点第二项，等 toast；

（3）资源管理器自动弹出 `%TEMP%\思源附件-…`，里面就是 `001-`、`002-`… 顺序文件。

### 7.4 导完之后

导出的是**裸副本**，适合打包发给别人、或者交给编辑部。想再按别的规则改名，直接在资源管理器里批量改就行，不会影响思源库。

### 7.5 从旧包名升级

v0.6.1 起包名从 `siyuan-plugin-attachment-anchor` 改成 `siyuan-plugin-attachment-kit`。升级步骤：

（1）新目录铺好文件；

（2）`setPetalEnabled(旧 id, false)` → `setPetalEnabled(新 id, true)`；

（3）旧目录**移走**（别直接删，先留证据）；

（4）重载界面，在「已下载」里确认只剩一个「文档附件管家」。

> 插件不使用 `loadData/saveData`，换 id 不丢任何配置。

### 7.6 卸载与回退

设置 → 集市 → 已下载 → 卸载，然后删掉 `data/plugins/siyuan-plugin-attachment-kit/`。`anchor-backup/` 与 `%TEMP%` 里的导出目录与插件无关，自行清理。

## 8 现有不足

### 8.1 功能边界

（1）**不递归子文档**，长篇要一篇篇点；

（2）**图片不参与改名**（只处理 `[锚文本](assets/xxx)` 这种 Markdown 链接），但导出包含图片；

（3）**块引用带进来的附件不算**：正文里是 `((块ID))`，kramdown 里看不到 `assets/`；

（4）**没有设置面板**，编号位数、剥不剥时间戳都写死；

（5）**临时目录不自动清理**。

### 8.2 已知风险与注意事项

（1）改名**不可撤销**（只能拿备份手回），批量操作前建议先在一篇小文档上试；

（2）同一附件被多个锚文本指向会被全部拦下，需要先统一锚文本；

（3）名字含 `\ / : * ? " < > |` 会被过滤，过滤后可能与你期望的不完全一致；

（4）200 字节上限，超了跳过；

（5）导出依赖磁盘实读，断链的文件只会被跳过并计数，不会报错停下；

（6）导出时名字过长会被截断（扩展名保住），提示里会报「N 个名字过长已截断」——想保留完整名就先自行改短再导。

### 8.3 排查与日志

| 现象 | 看哪里 |
|---|---|
| 点图标没反应 | 顶栏图标是否加载（`GET /plugins/siyuan-plugin-attachment-kit/plugin.json`） |
| 提示「请先把光标放进一篇文档」 | 当前没有活动文档，或焦点在文档树上 |
| 导出 0 个 | 该文档确实没有引用本地附件；或全是块引用带进来的 |
| 文件夹没弹出 | 提示里的完整路径手动打开；日志见下 |

控制台日志前缀 `[attachment-kit]`：`导出`（报告）、`报告`（改名报告）、`[dry-run] 计划`（判定明细）。

## 9 技术实现（附录）

### 9.1 为什么用整篇 kramdown 而不是 SQL

`blocks.sort` 在同一文档里会重复，逐块扫还会把一条链接算成 `l`/`i`/`p` 三次。文档级 `getBlockKramdown(docId)` 一次返回整篇，天然有序、含图片、不含重复——实测 23019 字符 / 55 条链接 / 图片齐全。

一个正则收三种形态：

```js
const RE_ANY_ASSET = /(?:\]\(|<img[^>]*?src=["'])\s*(\/?assets\/[^)"'\n>]*)/g;
```

终止符是 `)`、`"`、`'`、`>`、换行——文件名里可以有空格（整段拿到），`"标题"` 不会被吃进来。

### 9.2 改名的执行链与回滚

复制成新名 → `instr` 查引用 → 逐块 `updateBlock` → 逐块 `getBlockKramdown` 校验 → 复查残留 → 删旧名。任一步失败，按已写入列表逆序还原，并删掉新文件。

- 只写最内层块（容器块不写，否则子块 ID 会变）；
- 单文件引用块上限 500，超了视为异常不动；
- 备份落 `data/anchor-backup/<时间戳>/`，不进 `assets/`。

### 9.3 导出的纯函数层

`buildExportPlan(kramdown, opts)` 与运行时完全解耦，可在 Node 里单测：抽链接 → 解码 `%20` → 剥时间戳 → 去重（同一文件只导一次，占首现位置）→ 三位编号 → 撞名加后缀。

名字长度由 `fitFileName(displayName, budget)` 兜底：预算 = `250 - 目录长度 - 1 - 5`（留 Windows 260 的余量），超了从词干截断、保扩展名、补 `…`。

执行层按计划 `copyFileSync`，**复制成功才 `n += 1`**，所以缺文件不会留下空号。

### 9.4 菜单与主题

自绘 DOM，不用 `Menu` 类（`Menu` 会被强制塞进「插件 ›」子菜单）。颜色全走 `--b3-*`：底 `--b3-theme-background`、悬停 `--b3-list-hover`、正文 `--b3-theme-on-background`、描边 `--b3-border-color`，亮暗主题自动跟随。
